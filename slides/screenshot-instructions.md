# Slide Screenshot Instructions

Use these instructions to replace the temporary screenshot placeholders in
`index.html`. Capture screenshots at a consistent 16:10 or 4:3 ratio, depending
on the placeholder. Keep the browser zoom at 100% and use the same browser theme
throughout.

Before sharing screenshots, remove or obscure personal information, private
repository names, email addresses, account menus, notifications, and unrelated
browser tabs.

## Screenshot 01: Finished Accordion in the LMS

**Slide:** 1

**Preferred ratio:** 16:10

Capture a Canvas, Blackboard, Brightspace, or Moodle course page containing the
finished accordion. Open one accordion section so the interaction is obvious.
Include enough LMS interface to establish context, but crop out course and
student information.

The screenshot should communicate: “This is the useful thing we will make.”

## Screenshot 02: GitHub Fork Button

**Slide:** 8

**Preferred ratio:** 4:3

Open the public starter repository on its main page. Include:

- the repository name;
- the **Fork** button in the upper-right area;
- a small amount of the file list for orientation.

Move the pointer away from the Fork button before capturing. Do not include a
personal account menu.

## Screenshot 03: Browser Editor

**Slide:** 8

**Preferred ratio:** 4:3

From the repository page, press the period key to open the GitHub web editor.
Capture the full editor with:

- the file explorer visible;
- `01_work/index.html` visible in the file list;
- the editor area open;
- the browser address bar visible enough to show that this is browser-based.

Avoid showing the terminal or developer console. The point is that no local
installation is required.

## Screenshot 04: File and Editable Content

**Slide:** 9

**Preferred ratio:** 4:3

Open `01_work/index.html` in the browser editor. Highlight or select one short,
recognizable piece of sample accordion content that participants will change.
Keep the file explorer visible so the file location is clear.

Choose content that is safe to show publicly and does not contain course or
student data.

## Screenshot 05: Commit Controls

**Slide:** 9

**Preferred ratio:** 4:3

Open the Source Control panel after making a small change. Include:

- the changed file;
- a plain-language commit message such as `Customize accordion content`;
- the button used to commit or commit and push.

Do not complete an additional commit solely for the screenshot if the change is
not intended to be saved. A screenshot from the normal workshop rehearsal is
preferred.

## Screenshot 06: Published GitHub Pages URL

**Slide:** 9

**Preferred ratio:** 4:3

Capture the GitHub Pages success state showing that the site is live. Include:

- the published URL;
- the success message or Pages status;
- enough of the GitHub interface to make the location recognizable.

Use the public workshop repository or a safe demonstration fork. Verify that the
URL works before capturing it.

## Workshop QR Code

**Slide:** 11

Provide a high-resolution QR code that opens the public workshop starting page.
Also provide the exact short URL as text; the slide should never rely on a QR
code alone.

Recommended destination: a single landing page that offers both the live-builder
route and the GitHub route.

## Delivery

Upload the six screenshots and the QR code using these filenames:

- `01-finished-lms-accordion.png`
- `02-github-fork.png`
- `03-github-web-editor.png`
- `04-editable-file.png`
- `05-commit-controls.png`
- `06-github-pages-url.png`
- `workshop-start-qr.png`

The images can then be cropped and inserted without changing the slide sequence.
